# Graph Validation - Semantic BPMN Checks

## Context

ADR-2 introduced `bpmn::graph::Graph` as part of the IR layer, but it is currently **only used in tests** — not in any production code. `commands/validate` and `compiler::compile` both skip graph-level validation entirely.

The BPMN 2.0 XSD **does not** provide these semantic checks:
- **No**: `process` must have at least one `startEvent` (XSD uses `minOccurs="0"`)
- **No**: `process` must have at least one `endEvent` (XSD uses `minOccurs="0"`)
- **No**: All `sequenceFlow.sourceRef`/`targetRef` must point to real nodes (XSD uses `xsd:IDREF` but quick-xml may not enforce ID constraints)
- **No**: Graph connectivity, reachability, orphans, dead ends

These are application-level semantic rules that belong in `Graph::validate()`.

## Plan (updated after review)

### Phase 0 - Branch hygiene

Current staging split leaves graph code unstaged (`src/bpmn/graph.rs`, `tests/bpmn_graph.rs`) while one staged test (`tests/compiler_compile.rs`) imports `Graph` for a structural assertion.

Before implementation starts, pick one of these:

1. **Preferred**: stage `src/bpmn/graph.rs` + `tests/bpmn_graph.rs` so staged tests are self-contained.
2. Remove the `Graph` assertion from `tests/compiler_compile.rs` temporarily, then re-add when graph validation is wired into production.

### Phase 1 - TDD for graph semantics

Extend `Graph::validate()` from dangling refs only to semantic graph checks, via failing tests first:

- **Error**: process has no start event
- **Error**: process has no end event
- **Error**: duplicate element IDs across nodes/flows
- **Error**: sequence flow references missing source/target node

Defer reachability/dead-end to a later pass unless we decide warning plumbing now.

### Phase 2 - Wire graph validation into production compile path

Add graph validation to `compiler::compile::compile_to_definitions()`:

- Build `Process` from MDX inputs (existing behavior)
- Run `Graph::new(&process).validate()`
- Return `CompileError::InvalidGraph(Vec<String>)` on failure

This ensures `detent compile` fails fast on semantically invalid MDX graph definitions.

### Phase 3 - Wire graph validation into BPMN validate command

In `commands/validate` for `.bpmn/.bpmn2` files:

- Keep parse/XSD pipeline as-is
- Keep `Definitions::validate_for_bpmn()` as basic structural guard
- Add `Graph::validate()` when `defs.process` exists
- Surface graph errors clearly in CLI output

### Phase 4 - Optional traversal diagnostics (future)

After core validation ships, consider warning-level diagnostics:

- unreachable nodes from all start events
- nodes that cannot reach any end event
- helper traversal APIs (`reachable_from`, `entry_nodes`, `exit_nodes`)

This is optional and should not block the core compile/validate integration.
