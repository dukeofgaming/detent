# Graph Validation - Semantic BPMN Checks

## Context

ADR-2 introduced `bpmn::graph::Graph` as part of the IR layer, but it is currently **only used in tests** — not in any production code. `commands/validate` and `compiler::compile` both skip graph-level validation entirely.

The BPMN 2.0 XSD **does not** provide these semantic checks:
- **No**: `process` must have at least one `startEvent` (XSD uses `minOccurs="0"`)
- **No**: `process` must have at least one `endEvent` (XSD uses `minOccurs="0"`)
- **No**: All `sequenceFlow.sourceRef`/`targetRef` must point to real nodes (XSD uses `xsd:IDREF` but quick-xml may not enforce ID constraints)
- **No**: Graph connectivity, reachability, orphans, dead ends

These are application-level semantic rules that belong in `Graph::validate()`.

## Plan

### 1. Extend `Graph::validate()` with richer checks

Current `validate()` only checks dangling refs. Extend with:

- **Missing start event**: process must have ≥1 startEvent
- **Missing end event**: process must have ≥1 endEvent
- **Unreachable nodes**: nodes not reachable from any start event (warn vs. error?)
- **Dead-end nodes**: nodes with no path to any end event (warn vs. error?)
- **Duplicate IDs**: two elements share the same `id` (ID/IDREF constraint)
- **Orphan sequence flows**: sequence flows referencing nodes not in the process

Design question: should these be hard errors or warnings? The spec says an executable process needs start/end events, so those should be errors. Reachability might be a warning (not all nodes need to be in the main flow).

### 2. Integrate `Graph::validate()` into `commands/validate` (BPMN files)

- Currently uses `Definitions::validate_for_bpmn()` which only checks `Process::validate_for_bpmn()` (has start, has end)
- Replace/supplement with `Graph::new(&process).validate()` for richer structural checks
- Add graph validation errors to the output

### 3. Integrate `Graph::validate()` into `compiler::compile`

- After building the `Process` from MDX inputs, call `Graph::new(&process).validate()`
- If validation fails, return a `CompileError::InvalidGraph(errors)` with the graph errors
- This catches dangling refs from MDX at compile time before serializing bad BPMN

### 4. (Optional) Add `Graph` methods for richer traversal

- `entry_nodes()` — nodes with no incoming sequence flows
- `exit_nodes()` — nodes with no outgoing sequence flows
- `topological_order()` — deterministic ordering for serialization
- `reachable_from(node_id)` — all nodes reachable from a given node

These could be useful for future debugger/LSP use cases (per ADR-2 rationale).
